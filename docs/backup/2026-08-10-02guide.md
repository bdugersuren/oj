# Системийн Шалгалт & Баталгаажуулалтын Гарын Авлага (Testing Guide)

Энэхүү баримт бичиг нь платформд нэмэгдсэн дараах 4 гол функцийг вэб дэлгэц болон API ашиглан алхам алхмаар хэрхэн шалгаж, тестлэх зааврыг агуулна:
1. **DMOJ Bridge холболтын эрүүл мэнд (Health Check)**
2. **Локал Sandbox (Subprocess) & Sample Run шүүлт**
3. **Багшийн Вэб Workspace (Polygon) ажиллагаа**
4. **Testlib C++ Custom Checker & Generator ажиллагаа**

---

## 1. DMOJ Bridge Холболтыг Шалгах (Health Check)

Админ хэрэглэгчийн хувиар DMOJ-ийн Bridge контейнерууд FastAPI сервертэй TCP сокетоор амжилттай холбогдсон эсэхийг вэб хянах самбараас шалгах:

### Алхамууд:
1. Вэб хөтөч дээрээ платформын админ хэсэг рүү нэвтрэн орно.
2. **Админ Тохиргоо (Admin Settings)** эсвэл **Шүүгчдийн Хяналт (Judges Health)** цэс рүү шилжинэ.
3. Систем арын фононд `GET /api/v1/admin-settings/judges/health` API-ийг дуудаж, Bridge бүрт TCP ping илгээнэ.
4. Дэлгэц дээр `oj-dmoj-bridge-1` болон `oj-dmoj-bridge-2` шүүгчид **"Online"** (Ногоон төлөв) эсвэл **"Offline"** (Улаан төлөв) байгааг харуулна.

> [!NOTE]
> Хэрэв шүүгчид "Offline" байвал Docker контейнерын логуудыг дараах тушаалаар шалгаарай:
> `docker compose logs bridge1 bridge2`

## 2. Локал Sandbox & Sample Run Шүүлт Тестлэх

Энэхүү тест нь сурагч бодлого илгээхэд DMOJ контейнер рүү явуулалгүйгээр, FastAPI-ийн локал subprocess шүүгчээр хурдан шалгаж дүн гаргах ажиллагааг шалгана.

### Алхамууд:
1. Бодлогын жагсаалтаас аль нэгэн бодлого (жишээ нь `A+B` эсвэл дурын бодлого) сонгож орно.
2. Код бичих талбарт (Monaco Editor) дараах загвар кодыг бичнэ (C++):
   ```cpp
   #include <iostream>
   using namespace std;
   int main() {
       int a, b;
       if (cin >> a >> b) {
           cout << a + b << endl;
       }
       return 0;
   }
   ```
3. **"Жишээ ажиллуулах" (Run Sample)** эсвэл **"Илгээх" (Submit)** товчийг дарна.
   * `Run Sample` дарахад `is_sample_test=True` тохируулагдаж, Celery дараалалд орохгүйгээр FastAPI сервер дотор локал шүүгчээр шууд уншигдана.
   * Хэрэв байгаль орчны `.env` дээр `ENABLE_JUDGE=False` болгосон бол ердийн `Submit` дарахад ч локал subprocess шүүлт ажиллана.
4. Дэлгэц дээр тест кэйс тус бүрийн статус (`AC`, `WA`, `TLE`), ажилласан хугацаа (ms), санах ойн хэмжээ (KB) шууд бодит хугацаанд (Websocket-оор) шинэчлэгдэн харагдахыг ажиглана.

## 3. Багшийн Вэб Workspace (Polygon) Тестлэх

Энэ бол багшийн вэб орчноос шинэ бодлого зохиох, тест генератор болон зөв шийдэл ашиглан тест кэйсийг автоматаар бэлтгэх гол орчин юм.

### Алхамууд:

#### Алхам 3.1: Workspace-ийг нээх
1. Багшийн эрхээр системд нэвтэрч **"Бодлогын сан удирдах" (Teacher Problems)** цэс рүү орно.
2. Аль нэгэн бодлогын хажууд байх **"Workspace (Polygon)"** (Sparkles иконтой) товчийг дарж орно.
3. Зүүн талын файл Explorer-т загвар файлууд (`statement.md`, `solution.cpp`, `generator.cpp`, `init.yml`) автоматаар үүссэн байхыг харна.

#### Алхам 3.2: Файл засаж хадгалах
1. Зүүн талын жагсаалтаас `statement.md` сонгоно.
2. Monaco Editor доторх текстийг засаж, бодлогын нөхцөлийг Маркдаун форматаар бичнэ.
3. Дээд талын **"Хадгалах (Save)"** товчийг дарна (товч идэвхгүй болж "Хадгалагдсан" төлөвт шилжинэ).

#### Алхам 3.3: Тест кэйсүүд автомат үүсгэгчийг шалгах (Generator)
1. Explorer-оос `generator.cpp` файлыг сонгоно. Энд Mike Mirzayanov-ийн `testlib.h` ашигласан загвар код байна.
2. Explorer-оос `solution.cpp` файлыг сонгож, бодлогын зөв хариуг гаргах С++ кодыг бичнэ.
3. Баруун талын **"Генератор" (Generator)** таб руу шилжинэ.
4. **"Генераторын параметрүүд"** талбарт тест үүсгэх аргументуудыг мөр бүрт нэг байхаар оруулна:
   ```text
   5 10
   10 100
   1000 5000
   ```
5. **"Тестүүд үүсгэх" (Generate)** товчийг дарна.
6. Сервер арын фононд `generator.cpp` болон `solution.cpp` кодуудыг `g++`-ээр хөрвүүлэн ажиллуулж, үүссэн оролтуудыг зөв кодоор бодож гаралт (`.out`) файлуудыг үүсгэнэ.
7. Амжилттай дуусмагц Explorer-ийн доор **"Тест кэйсүүд"** хэсэгт `cases/1.in`, `cases/1.out` зэрэг файлууд нэмэгдэн жагсахыг харна. Мөн `init.yml` файл автоматаар шинэчлэгдсэн байна.

## 4. Testlib C++ Custom Checker Тестлэх

Хэрэв бодлого нь олон зөв хариулттай (жишээ нь, "ямар нэгэн тэгш тоо ол", "дурын замыг хэвлэ" гэх мэт) эсвэл бодит тооны нарийвчлал шалгах шаардлагатай бол Custom Checker ашигладаг.

### Алхамууд:

#### Алхам 4.1: Custom Checker үүсгэх
1. Workspace-ийн Explorer дээр сул зайд баруун товшиж эсвэл загвар файлаас засах замаар `checker.cpp` нэртэй шинэ файл үүсгэнэ.
2. Monaco Editor дотор дараах Testlib С++ checker-ийг бичнэ (жишээ нь, хоёр бодит тооны зөрүү 10^-6-аас бага байгааг шалгах):
   ```cpp
   #include "testlib.h"
   
   int main(int argc, char* argv[]) {
       registerTestlibCmd(argc, argv);
       
       double expected = ans.readDouble();
       double candidate = ouf.readDouble();
       
       if (doubleCompare(expected, candidate, 1e-6)) {
           quitf(_ok, "Хариу зөв: Expected %.6f, Found %.6f", expected, candidate);
       } else {
           quitf(_wa, "Буруу хариу: Expected %.6f, Found %.6f", expected, candidate);
       }
   }
   ```
3. **"Хадгалах (Save)"** товчийг дарна.
4. `init.yml` файлыг нээж, дээрх custom checker-ийг ашиглах тохиргоог нэмж хадгална.

#### Алхам 4.2: Бодлогыг нийтлэх (Publish)
1. Баруун талын **"Нийтлэх" (Publish)** таб руу шилжинэ.
2. Бодлогын гарчиг, цагийн хязгаар, санах ойн хязгаарлалт, хүндрэлийн зэрэглэлийг тохируулна.
3. **"Бодлого Нийтлэх"** товчийг дарна.
4. Систем бүх файлуудыг багцлан `cases.zip` болгож MinIO-ийн хувийн саванд хуулах ба өгөгдлийн санг шинэчлээд багшийн нүүр хуудас руу чиглүүлнэ.

#### Алхам 4.3: Custom Checker-ийг ажиллуулан шалгах
1. Сурагчийн хаягаар эсвэл бодлогын дэлгэрэнгүй хуудас руу орно.
2. Бодлогод хариулт кодыг илгээнэ.
3. Сурагчийн кодын гаралтыг стандарт тэмдэгт бүрээр тулгахгүй, багшийн бичсэн `checker.cpp`-ийг ажиллуулан шүүж, дүн гаргахыг шалгана.
4. Илгээлтийн дэлгэрэнгүй хуудаснаас тест кэйс бүрийн доорх **"Checker Output"** хэсэгт checker-ийн буцаасан лог (`Хариу зөв: Expected ..., Found ...`) харагдаж байгааг баталгаажуулна.

## 5. Testlib Generator Бичих & Ашиглах Заавар

Олимпиадын бодлого зохиоход тест кэйсийг гараар гараас шивж оруулах нь цаг хугацаа их шаардах бөгөөд алдах магадлалтай байдаг. Иймд С++ хэлний **Testlib** санг ашиглан санамсаргүй (гэхдээ тогтвортой / deterministic) тестүүд үүсгэгч програм бичдэг.

### 5.1 registerGen гэж юу вэ?
Generator кодын эхэнд заавал `registerGen(argc, argv, 1);` гэж бичнэ. Энэ нь:
1. Санамсаргүй тоо үүсгэгч (`rnd` объект)-ийг ажиллуулахад ашиглагдах seed утгыг command-line аргументуудад суурилан тохируулдаг.
2. Ингэснээр **яг ижил аргумент өгөхөд үргэлж яг ижилхэн санамсаргүй оролт үүснэ** (тогтвортой байдал). Энэ нь тестүүдийг дахин дахин үүсгэхэд маш чухал үүрэгтэй.

### 5.2 Параметрүүдийг хэрхэн уншиж тохируулах вэ?
Системийн дэлгэц дээрх **"ГЕНЕРАТОРЫН ПАРАМЕТРҮҮД"** талбарт оруулсан мөр бүрийг манай систем тус тусад нь ажиллуулах аргумент болгон дууддаг.
* Жишээ нь, хэрэв та параметр талбарт `10 100` гэж бичвэл, систем арын фононд `./generator.out 10 100` гэж ажиллуулна.

С++ код дотор эдгээр аргументуудыг уншихдаа Testlib-ийн дараах бэлэн функцийг ашиглана:
- `opt<int>(index)`: Тухайн индекст байрлах аргументыг бүхэл тоо болгон уншина (1-ээс эхэлнэ).
- `opt<double>(index)`: Бутархай тоо болгон уншина.
- `opt<string>(index)`: Текст болгон уншина.

---

### 5.3 Бодит Жишээ: Массивын нийлбэрийг олох бодлого

Багш дараах нөхцөлтэй бодлогын тестүүдийг бэлтгэхээр зорьсон гэж үзье:
> **Бодлого**: Массивт өгөгдсөн $N$ ширхэг тооны нийлбэрийг ол.
> * Хязгаарлалт: $N \le 10^5$, Элемент бүр $\le 10^9$.

#### Алхам 1: `generator.cpp` файлыг бичих
Workspace доторх `generator.cpp` файлыг дараах байдлаар засаж хадгална:

```cpp
#include "testlib.h"
#include <iostream>

using namespace std;

int main(int argc, char* argv[]) {
    // registerGen-ийг заавал эхэнд нь дуудна.
    registerGen(argc, argv, 1);
    
    // Параметрүүдийг унших:
    // opt<int>(1) - Массивын хэмжээ N
    // opt<int>(2) - Элементүүдийн хамгийн их утга M
    int n = opt<int>(1);
    long long m = opt<long long>(2);
    
    // Оролтыг хэвлэж гаргах (энэ нь сурагчийн програмын оролт болох .in файл болно)
    cout << n << endl;
    for (int i = 0; i < n; i++) {
        if (i > 0) cout << " ";
        // rnd.next(мин, макс) нь [мин, макс] мужаас санамсаргүй тоо буцаана
        cout << rnd.next(1LL, m);
    }
    cout << endl;
    
    return 0;
}
```

#### Алхам 2: `solution.cpp` файлыг бичих
Туршилтын болон жинхэнэ гаралтууд үүсгэхэд зөв шийдэл шаардлагатай. `solution.cpp` файлыг сонгон бодлогын зөв кодыг бичнэ:

```cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    int n;
    if (cin >> n) {
        long long sum = 0;
        for (int i = 0; i < n; i++) {
            long long val;
            cin >> val;
            sum += val;
        }
        cout << sum << endl;
    }
    return 0;
}
```

#### Алхам 3: Параметрүүдийг оруулах
Баруун талын **"Генератор"** таб руу шилжиж, **"Генераторын параметрүүд"** хэсэгт мөр бүрд өөр өөр тестүүдийн хэмжээсийг тохируулж өгнө. 
Энд бид нийт 4 тест кэйс үүсгэхийг хүсэж байна гэж үзье:

```text
5 10
10 100
1000 1000000
100000 1000000000
```

*Манай систем үүнийг хэрхэн боловсруулах вэ:*
1. **Мөр 1 (`5 10`)**: Арын фононд `./generator.out 5 10` гэж ажиллаж, 5 ширхэг 10 хүртэлх тоо үүсгэнэ. Үүнийг `solution.out` рүү дамжуулж хариуг гаргаад, `cases/1.in`, `cases/1.out` файл болгон хадгална.
2. **Мөр 2 (`10 100`)**: `./generator.out 10 100` ажиллаж, 10 ширхэг 100 хүртэлх тоо үүсгэнэ. `cases/2.in`, `cases/2.out` файл болон хадгалагдана.
3. **Мөр 3 (`1000 1000000`)**: Дунд зэргийн хэмжээтэй тест үүсгэж `cases/3.in`, `cases/3.out` болгоно.
4. **Мөр 4 (`100000 1000000000`)**: Бодлогын хамгийн дээд хязгаар (Max test)-ыг шалгах тест үүсгэж `cases/4.in`, `cases/4.out` болгон хадгална.

#### Алхам 4: Үүсгэх (Generate)
**"Тестүүд үүсгэх" (Generate)** товчийг дарахад систем дээрх дарааллаар ажиллаж, таны өмнөөс хэдхэн секундэд 4 том тест кэйсийг бэлтгэж, `init.yml` файлд холбогдох оноо болон жишээний (sample) тохиргоог автоматаар бүүглэж өгнө.
Жишээ тестийг вэб дэлгэцийн зүүн доод хэсэгт байх `cases/1.in` зэрэг дээр дарж шалгах боломжтой.

## 6. Багц Тест болон Сабтаск (Subtasks) Тохируулах

Мэдээлэлзүйн олимпиадын стандарт (IOI/APIО загвар)-т тест кэйс бүрд тусад нь оноо өгөхөөс гадна, тестүүдийг бүлгүүдэд хуваан **Багц Тест (Subtask)** болгож оноо өгдөг. 

### 6.1 Багц тестийн оноо бодох дүрэм
* Багц доторх **бүх тест кэйсүүд зөв (AC)** ажилласан тохиолдолд л уг багцын оноог сурагчид өгнө.
* Хэрэв тухайн багцын аль нэгэн тест дээр буруу хариулт (`WA`), хугацаа хэтрэх (`TLE`), эсвэл процесс унах (`RTE`) алдаа авбал сурагч **уг багцаас 0 оноо авна**.

---

### 6.2 init.yml файлын бүтэц (Subtask тохируулах)
Багшийн ажлын талбар (Workspace) доторх `init.yml` файлыг сонгон, уламжлалт хавтгай жагсаалтын оронд дараах байдлаар **nested (уялдаатай) бүтцээр** бичиж тохируулна:

```yaml
archive: cases.zip
time_limit: 1.0
memory_limit: 64
test_cases:
  - points: 30
    cases:
      - {in: cases/1.in, out: cases/1.out, sample: true}
      - {in: cases/2.in, out: cases/2.out}
  - points: 30
    cases:
      - {in: cases/3.in, out: cases/3.out}
      - {in: cases/4.in, out: cases/4.out}
  - points: 40
    cases:
      - {in: cases/5.in, out: cases/5.out}
      - {in: cases/6.in, out: cases/6.out}
```

*Энэхүү тохиргооны тайлбар:*
* **Багц 1 (30 оноо)**: `cases/1.in` болон `cases/2.in` тестүүд багтана. Эдгээрийг хоёуланг нь зөв бодвол 30 оноо авна. `1.in` нь бодлогын нөхцөл дээрх жишээ тест тул `sample: true` тохируулсан байна.
* **Багц 2 (30 оноо)**: `cases/3.in` болон `cases/4.in` тестүүд багтана.
* **Багц 3 (40 оноо)**: `cases/5.in` болон `cases/6.in` тестүүд багтана.
* Нийт бодлогын оноо: $30 + 30 + 40 = 100$ оноо.

---

### 6.3 Систем дээр хэрхэн ажиллах вэ?

1. **DMOJ Bridge Шүүгч**: Хэрэв бодлого нийтлэгдэж, DMOJ Bridge-ээр шалгагдвал, DMOJ-ийн өөрийнх нь систем уг бүтцийг таньж багцын дүрмээр үнэлнэ.
2. **Local Sandbox (Subprocess) Шүүгч**: Манай дотоод Local Judge систем мөн уг бүтцийг таньж ажиллана. Багц бүрийн бүх тестийг ажиллуулсны дараа, багц дотор алдаа гараагүй бол нийт оноон дээр тухайн багцын оноог нэмэх логикоор ажиллана.
3. **Нийтлэх (Publish)**: Багш ажлын талбарт тестүүдийг үүсгээд, `init.yml`-ээ дээрх байдлаар засаж хадгалаад **"Publish"** хийхэд:
   * Систем сагсалсан жишээ тестүүдийг (жишээ нь `sample: true` гэсэн `1.in`, `1.out`-ийг) автоматаар ялган авч өгөгдлийн санд сурагчдад харуулахаар хадгална.
   * Нийт оролт, гаралтын бүх файлууд болон зассан `init.yml` нь багцлагдаж `cases.zip` болон MinIO-д хадгалагдана.
